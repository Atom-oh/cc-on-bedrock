# Sync Docs

Bring project documentation back in line with the code. The goal is accurate, concise docs, not more docs.

## Steps

1. **Find drift.** Compare the root `CLAUDE.md`, module `CLAUDE.md` files (`terraform/`, `lambda/`, `docker/`, `shared/nextjs-app/`, `scripts/`, `tools/`, `tests/`, `agent/`), `docs/architecture.md` and `README.md` against the code. Check `git log --oneline -20` for recent changes that docs may not reflect.
2. **Verify before keeping.** For every command, path, count, model ID or ADR reference, confirm it against the code (`package.json`, scripts' usage lines, `terraform/*.tf`, `ls`). Remove or fix what no longer holds; cite the file you checked when the claim is non-obvious.
3. **Update what changed.** Edit only sections whose facts changed. Keep each file's language and style. Use consolidated ADR numbers (`docs/history/ADR-MAPPING.md` maps legacy ones).
4. **Gaps.** If a module has a non-obvious contract and no `CLAUDE.md`, propose one; don't create files for trivial directories.
5. **Decisions.** If recent commits contain an undocumented architectural decision, point it out and suggest an ADR. Do not write the ADR unless the user asks; if one is written, `docs/decisions/BASELINE.md` is updated in the same change.
6. **Report.** List the files changed with a one-line reason each, plus anything you found but left alone.

Leave `docs/decisions/**`, `docs/history/**` and generated files (anything with a "generated by" header) unless the user asks.
